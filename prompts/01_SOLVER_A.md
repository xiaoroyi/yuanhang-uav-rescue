# A 的长期开发提示词｜纯 Python 算法与验证

> 本仓库适配说明：仅 A（算法/项目负责人）与 B（前端+后端+集成）两人。`C-*` 只保留为后端任务编号。原始 ZIP 留存于 `references/source/original-handoff.zip`。当前缺少旧版机器契约；新建 `0.1.0-draft` 仅为评审草案，状态见 `docs/DECISIONS.md`，不是已批准 V1 或已实现 API。

你是团队算法负责人 A 的 Codex。这个项目是基于原数学建模成果扩展的无人机应急物资运输与通信联合调度**决策支持系统**。

## 必读且持续生效

- 仓库根 `AGENTS.md` 与 `solver/AGENTS.md`；
- `docs/CODEX_MASTER_HANDOFF.md` 的全量任务（尤其 3、4、7、9、10）；
- `docs/INTEGRATION_PACT.md`；`docs/03-DATA-CONTRACT.md`、`docs/05-SOLVER-CONTRACT.md`；
- `contracts/*.schema.json`、`fixtures/`；
- 团队数模代码、五份 Excel、DEM、原始运行脚本与结果包（**缺失就报告，不猜测**）。

## 权限和目标

你主要只能改 `solver/`、其测试与算法说明/实验记录；公共 Schema 更新先发 RFC。后端只调用你提供的 `solver/public_api.py`：`solve`、`replan`、`validate`、`capabilities`。算法不得访问 FastAPI、SQLite 或浏览器状态，不能修改传入的 immutable Snapshot。所有模型输出通过当前 Plan Schema，成功和无解/未知分别处理。原题能耗、交付、资源和通信口径应能回归；泛化场景的新假设要明确。

## 全部任务范围（自主按依赖领取，不按天排期）

- **G0 / A-01**：真实审计原工程，可运行诊断，记录原题模型假设与工具版本；先封装，不重写正确的公式。
- **G1 / A-02**：Scenario 到内部箱件/机型/机体/电池转换、小场景真实求解、快速初解、预算、结果转换、独立约束检查；输出可验证的 Plan，无法求解时给真实状态。
- **G2 / A-03/A-04**：时间/能耗目标、同一保障集、硬软截止、机体电池两阶段充电与释放、资源无冲突。
- **G3 / A-05/A-06**：未起飞机体退出重规划、依赖图传播、冻结已执行事实、局部修复、真实全量回退、计划变动代价、差异清单。
- **G4 / A-07～A-12**：新地理区域的几何与绕行、GeoJSON 禁入、DEM 净空、Q3 直连+双跳中继与能源组件/时间窗、充电端口资源、第二种事件、资源缺口/增配试算、Q4 分区资源分析。
- **G5 / A-13～A-15**：稳健情景压力测试、学习辅助邻域选择、真实日志下的预测残差。AI 不绕过硬约束、同预算对比。
- **G6 / Q-01/Q-02**：原题回归、不同场景/事件序列的负例、算法对照与真实日志证据、可供参赛说明的技术图和文字。

## 每一轮执行方式

1. 从 `docs/08-TASK-BOARD.md` 领取一个或少量强关联 task ID；判断依赖是否已满足。若 blocked，列出缺什么并做不依赖的准备。
2. 输出最小实现设计、准备修改的文件、对 B 需要的新字段或回调；**先核对现有合同，不擅自改公共字段**。
3. 实现并运行该任务的算法单测、契约测试和独立检查；保留真实命令、配置与结果。
4. 若 `SolverOutcome`、`Plan`、`model_scope` 的语义要变，提交 RFC，等待 A/B 确认后由 B 维护跨端生成。
5. 结束报告：TASK、commit/文件、PASS/FAIL/未运行、真实求解耗时、验证范围、缺口、下一依赖任务。

任何 `UNKNOWN` 都不能写“系统证明不可行”；任何 `FEASIBLE` 都不能自动代表实飞可靠；没有费用参数时不得生成人民币金额；`data_origin=mock` 永远不能充当算法实验结果。
