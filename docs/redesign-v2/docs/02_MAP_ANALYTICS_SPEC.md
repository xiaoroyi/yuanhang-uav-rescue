# 02｜地图主工作区、动态可视化与结果分析

## 1. 地图要承担什么业务

地图不是给列表添加的背景。它应同时支持：理解地形与落点、创建/编辑输入、识别不可达及限制、检查推荐航路、查看每个对象详情、跟踪进度、定位异常、对比重规划。地图在准备、方案、执行、复盘中共享同一个实现，只切换工具权限与数据来源。

技术参考：MapLibre [S08]、PMTiles [S09]、Cesium [S11]、ECharts [S12]。下列布局、字段、性能门槛为本项目设计，不是第三方产品的已测性能。

## 2. 技术选型与渲染原则

优先保留当前 MapLibre GL JS，完成高质量2D/2.5D主工作区。禁止因为图片不好看就并装 Leaflet、Mapbox、OpenLayers、Cesium 各自维护一套点击和数据逻辑。

需要真正的绝对高度航迹时，可增加懒加载 Cesium 三维审查视图，通过统一 `MapWorkspaceAdapter` 接受相同的对象、选择和时钟。二维地图可以显示地面投影，不能把贴地折线说成三维飞行轨迹。仅有灰度hillshade不叫三维。

底图模式：

1. **地形业务图（默认）**：可读的道路、水系、居民点和地形；低饱和高程设色+轻阴影；强度可调，标签清楚。
2. **卫星/正射影像**：有授权的数据源；含影像日期、覆盖与更新状态，不隐含实时。
3. **离线底图包**：本地可用的地理定位底图、标签、字体、图标、DEM。加载前给出覆盖范围和比例尺范围。
4. **高程分析**：用于审查，展示高程色带、剖面和NoData，不作为唯一默认底图。

图片必须地理配准：GeoTIFF/COG或经验证的瓦片；不能将一张导出的山地图PNG拉伸后当地图。若需PNG作为特定覆盖层，必须有已知坐标四角/投影、正确配准和范围限制。

## 4. 对象信息与交互行为

### 4.1 需求点

常态标签：简称/站点ID+紧急标记+缺口提示；不同时悬挂十行文字。多点聚集时聚类/避让，选中点完整显示。

悬停仅3项：点名、关键需求未保障数量、下一次预计交付。点击后右侧详情包括：位置与地面高程、所属任务、现场更新、接收条件、物资需求、当前库存分配、负责架次/机体、首批/全部交付时间、未满足原因、联系人权限入口、历史上报。

可用动作：准备态“编辑需求/移动点位”；计划态“定位负责架次/查看可达机型/修改并重算”；执行态“记录需求变化/落点关闭/人工签收”；复盘态“查看历史事件”。运行中拖动点位不能立即改实际任务，须产生变更草案。

### 4.2 基地与保障点

显示起降位、正在准备/预计返航机体、可用电池、充电排队和可用物资。点击“增加保障资源”进入what-if副本，不直接给实际基地添加设备。备降点显示适用机型、可用窗口、现场确认时间和容量。

### 4.3 机体

图标表达朝向，标签最多机体ID+SOC+阶段；详细速度、高度、ETA、连接延时放抽屉。飞行中/模拟中才更新位置。遥测过期显示最后已知位置与时间，不继续沿计划飞出“假实况”。

详情支持“跟随此机”“显示完整航迹”“定位下一站”“查看装载/电池”“查看指令记录”。控制按钮依适配器能力与权限出现，不凭型号名称认定支持。

### 4.4 航线与航段

鼠标距离线8–12px可命中（额外透明拾取层），避免细线难点；重合路线弹出候选列表，支持按机体/时段筛选。

点击后显示：架次、起终点、载荷、计划起降/服务时间、分段能耗、最小净空、通信来源、天气来源与验证状态。点击“查看剖面”打开底部图；鼠标在剖面上移动同步地图定位。

路线类别由统一视觉语义决定：当前计划实线、变更前虚线、调整新增强调线、执行轨迹另一线型。不能同时用颜色表达机型、风险和新旧版本；可让用户切换一种编码模式并更新图例。

### 4.5 中继与通信

中继显示点位、高度、服务时段、能源组件和所支持架次。选中某一运输机/时刻显示运输机→中继→网关的真实模型链路，或合法直连。

覆盖圆只能是明确条件下的理论距离界，不可当作有地形遮挡时的真实覆盖。可用样点属于采样图层；实际航段的连续通信核验另显示。

### 4.6 风险与地图任意位置

点选位置显示经纬度、坐标系、地面高程、资产来源、相关限制/有效时间；高程未知显示缺失，不用0。

可添加注记/需求点/备降点，画多边形、圆或走廊，测距与路线长度。编辑有预览、撤销、完成和取消；不在每次鼠标移动时写数据库。测距不替代飞行路径/能耗计算。

## 5. 地图控制和界面减负

左上只放：地点搜索、底图按钮；右上：图层、定位全任务、2D/3D（确实可用）、全屏；右下缩放/北向；左下简洁图例与署名。控件避开详情抽屉和时间轴，不四角同时放大卡。

“图层”一个抽屉包含可见性、透明度、来源、更新时间、是否用于本次计算。地图故障横幅只在相关时显示，关闭提示不改变计算状态。

地图应在空态也可缩放/查看已有点，不因为尚无Plan锁住全部空间功能。中心点来自任务范围，禁止写死镇龙乡；返回某任务可恢复用户视角，切换不同任务则适配新范围。

## 6. 地理与高程正确性

- 输入保留原始水平/垂直参考；标准业务交换使用WGS84经纬度，数组顺序经度在前。内部距离计算使用适当的米制投影或测地线，不直接把经纬度当米。
- 接入GCJ-02等底图时由适配层转换展示；计算仍保留规范坐标及转换链，避免双重转换。[S16]
- 区分 AGL（离地）、AMSL/正高、椭球高和相对起飞点高度。未知垂直基准不能直接给真实设备下发。
- Cesium绝对位置与地形数据必须按所需高程基准转换；不要把论文“海拔”直接当椭球高。没有转换条件时仅作标明基准的二维/剖面显示。
- 地形夸张默认1.0；用户视觉放大时显著标识，不改变算法值。
- 没有DEM的区域不能以平地插补后标净空通过；拼接、重采样和NoData策略必须有版本。
- 30m地形不能被表述为已覆盖电线、树木和所有建筑；若需障碍检验，引入DSM/障碍记录与数据不确定性。
- 进入新地图范围后，线路/链路缓存键包含资产版本、几何、模型与参数；不能继续用原题120个节点对的缓存。

## 7. 离线与地图服务

实现 `MapAssetManifest`：asset_id/version/kind/bounds/horizontal_crs/vertical_datum/resolution/source_time/license/attribution/sha256/tile_endpoint/availability。

本地服务提供瓦片/COG访问，保留读原DEM的计算路径。推荐有授权的区域PMTiles或本地预处理瓦片，前端字体/图标也本地化。PMTiles使用需支持HTTP Range；浏览器`file://`打开不是完整运行环境。[S09]

禁止从 `tile.openstreetmap.org` 批量预取城市和离线瓦片；选择许可合适数据。[S10] 卫星服务需密钥/付费时记录具体依赖，不使用未经授权的端点，不把在线不可用伪装为有缓存。

离线断网验收：已有本地区域仍可展示、查看、规划与回放；超出离线包范围明确提示，不无限请求公网。外部天气不可更新时显示缓存时效，并按模式阻断或进入显式模拟假设。

## 8. 动态播放：三种时钟与一个选择状态

### 8.1 计划预演

从算法给出的阶段轨迹播放。每段至少有 `phase_id,sortie_id,start_s,end_s,phase_kind,position_samples/segment_endpoints`；停靠、准备、悬停不移动；飞行按各阶段时间插值，而非沿整个LineString匀速走一遍。

SOC/载荷来自后端阶段数据。载荷在交付时发生变化；能耗非线性时不能用首尾SOC全程线性动画冒充物理模拟。缺少逐时SOC时，只在关键节点显示已计算SOC，并标中间值未计算。

播放器：暂停、播放、1×/5×/20×、拖动、上一/下一关键事件、时间显示、跟随机体。播放不会写交付事实。

### 8.2 仿真运行

后端仿真时钟推进，产生隔离执行事实和遥测。前端只订阅；刷新页面后仍能同步服务器进度。支持固定seed与事件脚本，暂停/恢复可复现。模拟“网络断流”和“天气变化”应真改变相应状态或约束，而不是仅弹窗。

### 8.3 实际跟踪和日志回放

实时观测时钟与计划预计时钟分开；接收时间和设备采样时间均保存。观测短暂缺口的平滑必须有限、可识别；超过配置阈值停在最后位置并标失联。回放时刻来自已保存记录，不查询“今天”的天气替代历史。

### 8.4 图表联动

地图、资源甘特、SOC曲线、需求进度、通信时间轴共享 `selected_sortie_id + t`。一处拖动/选择只更新视图状态，不触发新求解。打开不同Plan时清除过期图表缓存。

## 10. 核心图表的计算口径

### 10.1 需求量和保障

每个需求保存 `required_quantity,mandatory_quantity,allocated_quantity,delivered_quantity,unserved_quantity`，对应单位与箱件实例。不要将“计划保障”直接当“已交付”。

首批基本保障应按明确组合定义，例如每站必须的特定饮水/医疗数量；不是任意送一箱就计该站已保障。人口/脆弱群体只能在有可靠输入时作为权重，不依据地名自动猜测。

时间：分别保存最后交付、最后运输机返航、最后运输+中继返航、累计资源占用。原题主口径为一次停靠全部交接结束；新物资可扩逐箱签收但不可与旧口径混比。

### 10.2 SOC与充电

机体占用结束、原电池补能结束不是同一时间；最后返航后充电可能仍进行。甘特不能按机体时间剪掉电池充电尾部。

实际SOC可能异步更新或短暂上升，不能强行调整成单调以“好看”。计划模型SOC与实际遥测分别显示；输入SOH/capacity是否已降额需在算法定义中固定。

### 10.3 通信指标

逐机累计缺口时间与全系统墙钟中断时长分开。两架运输机各有10s缺口，逐机累计20s不等于系统断网20s。图5.13原有口径保留，并给用户可理解的标签。

缺口为0只在所声明传播/地形/时间核验范围成立。没有配置/没执行核验则为未检查，不能画全绿来源条。

### 10.4 图形准确性

坐标轴有单位和零点/截断说明；缺失数据断线；不连接不可行区；误差带只有有统计方法时才绘制。区间选择和筛选不改变全局指标，需显示筛选范围。避免三维柱状、双Y轴混淆、无法解释的“综合分”。

## 11. 支撑图表的 API 数据对象

使用 `PlanAnalysis` 独立投影视图，不把所有图数据塞进一个越来越大的Plan核心JSON。引用 `plan_id,snapshot_id,analysis_version`；核心接口建议见03文档。

执行事实另由 `ExecutionAnalysis` 提供，绑定 `execution_id,facts_cursor,analysis_version`。页面可叠加计划与实际，但不可在旧 PlanAnalysis 中静默更新已交付量；不同来源的序列和缓存键必须分开。

至少包含：

- `service_rows`：按需求/站点的数量、截止、交付与缺口。
- `resource_intervals`：resource_kind/id、sortie_id、phase、start/end、planned/observed、来源。
- `trajectory_segments`：阶段与带时间坐标、高程基准、阶段载荷/电量。
- `energy_breakdown`：分项、不确定性标识、统计范围。
- `communication_intervals`：实际选择来源、接入/回传余量、检查方式。
- `diagnostics`：受影响ID、位置、时段、期望/实际值、修复动作。
- `comparison`：条件差异、共同保障集合、指标口径与候选。

这些必须由可追溯的计算/业务记录生成。前端可做排序、格式化、图形插值和展示级筛选，不另写能耗、可行性、配送保障等核心公式。

## 12. 地图与图表工程验收

1. 正确加载当前任务，不固定某个地区；导入另一地区点位后相应定位。
2. 未选择任何点时标签不过密；五个与五十个点都可用；重合航路能选择。
3. 点击站点/架次/电池甘特/诊断，定位同一业务对象。
4. 地图在两种桌面尺寸首屏可见，不被标题卡片挤下去。
5. 平移缩放、侧栏调整不会销毁整个地图实例或反复请求全部资源。
6. 地图切底图后保留业务图层和选择，样式加载完成再添加，避免双层图标。
7. 断网、外部瓦片不可达、WebGL失效都有明确降级；后两者不能误报算法无解。
8. 无实际遥测时不显示动态实机；断流后位置冻结并有时间标记。
9. V07剖面和V04/V05甘特读取同一阶段数据；结束时SOC与Plan一致（允许有明确数值容差）。
10. 所有地图弹窗使用安全文本渲染，不把用户上传HTML直接插入 `setHTML`；MapLibre文档明确该方法不自动清洗HTML。[S08]
11. 默认移动动画约150–200ms且尊重减少动态设置；实时数值不闪烁、不每帧全页重渲染。
12. 性能目标按指定测试机实测：50站点/20机体/200箱件的演练数据，在地图连续播放时保持可操作；记录帧率和长任务，不把目标写成已达性能。
