# 04｜现实约束、算法升级与可验证创新

> 本文是从原数模模型向应急调度产品扩展的设计建议。原论文结论只适用于其明确场景与模型。天气、动态执行、地面保障和学习模块属于新增工作，必须分别实现、标定、验证，不能因界面出现相应图标就视为已完成。

## 1. 不把“现实全面”理解为一次堆入所有因素

优先处理会改变任务能否执行、谁能执行、何时执行的因素；然后处理优化目标和展示。目标是模块化增加可信约束，不是让用户填完几十个无来源参数才能开始。

提供两个明确模型配置：

- `contest_regression`：保留原题模型、原输入、充电与通信规则，便于重现和验证。题设 20% 返航储备、50 米地形净空、单基地及原机型参数明确标为题设配置。
- `rescue_configurable`：用户选择实际机型/标定或可追溯估算配置，逐项启用现实约束。不能把原题系数默默套到任何真实机型；不支持的条件通过能力协商说明。

现实配置可以用合成参数演练；在此情况下输出“所选参数模型下的演练结果”。不要把它描述为已获得实飞认证。

## 2. 现实约束按业务影响分组

| 因素               | 至少要输入/获取什么                             | 如何改变决策                   | 界面与验证                |
| ------------------ | ----------------------------------------------- | ------------------------------ | ------------------------- |
| 真实可用设备       | 实体状态、位置、兼容性、可用时间、维护限制      | 谁能承担任务，何时开始         | 资源表与冲突检查          |
| 当前电量与健康状态 | SOC、有效容量定义、SOH/标定来源、温度与充电状态 | 能否完成投送与返航、何时复用   | 能量余量和电池时间轴      |
| 需求与库存         | 数量、截止、不可拆箱、位置、物资类型            | 缺货不等于缺运输能力           | 需求缺口与装载追溯        |
| 投送方式与站点     | 降落/绞盘/投放、场地条件、人员接收、可用窗口    | 服务时间、机型适配、能耗与风险 | 点击站点展开信息与限制    |
| 地形与障碍         | DEM/DSM、垂直基准、障碍更新、未知区             | 候选路线、高度、净空资格       | 地形剖面、未知区域定位    |
| 空域限制           | 水平区域、垂直范围、有效时段、来源              | 在对应时间和高度排除航段       | 分层图例与影响路径        |
| 气象               | 起飞/沿途/投送/返航时段预报或观测               | 作业窗口、飞行与能量可行性     | 过期/缺失提示与受影响任务 |
| 地面保障           | 充电端口/总功率、起降位、装卸人员/工位          | 资源排队，避免隐含无限并发     | 地面资源甘特与瓶颈        |
| 通信               | 网关、中继、链路模型、窗口、容量及数据质量      | 运输与中继联合规划             | 双跳链路与连续区间检查    |
| 机间冲突           | 三维轨迹及时间、分离/缓冲策略                   | 起飞排序、时空错开或绕行       | 冲突区间与场景回放        |
| 在途状态           | 当前位置、载货、SOC、执行阶段、设备采用计划版本 | 冻结事实、修复未来部分         | 修改预览与部分应用状态    |
| 费用与服务公平     | 可解释费率、必须保障集合、基本保障组合          | 合法候选间的取舍               | 费用明细/服务时间分布     |

限制规则的来源应为机型说明、组织作业配置、经过验证的标定或明确实验假设；不要给所有无人机规定同一个最大风速、温度范围或返航比例。[S18]

## 3. 能耗模型的现实化：补数据，不造精度

### 3.1 原模型保留的内容

原论文按载荷相关等效航程与爬升附加项计算，机体与电池分别排程；运输结束后电池仍可能充电。这些能力应保留并以原题测试集回归。原题下降附加能耗、装卸/交接简化、初始满电等假设不能自动成为现实结论。

### 3.2 新模型分项

建议逐步形成：地面准备、起飞/爬升、巡航、下降、悬停/投送、返航、落地/周转，以及中继建链和驻留。是否计入某项、相应功率或耗时来自哪份数据，都写入模型配置。

如果投送改为绞盘，不能沿用降落交接时间却展示绞盘动画；若无人机需要悬停，悬停能耗必须真实进入模型。没有参数时要求输入或保留不支持，不凭常识填一组“看起来合理”的值当已标定结果。

### 3.3 SOC、SOH 与容量不能重复降额

明确 `capacity_kwh` 是额定容量、当前有效容量还是题设可用能量。只有字段定义需要时才结合 SOH 估计有效容量；如果上传的容量已是实测当前可用能量，不得再乘一次 SOH。

温度影响电池性能与充电约束需要设备数据或标定曲线。环境温度不等于电芯温度，不能把天气接口的气温直接当作电池温度。缺少曲线时可以做标注假设的降额敏感性实验，不得声称得到了某型号真实剩余航程。

### 3.4 返航约束升级

原题检验完整架次后的最低剩余电量。现实模型还应检查关键阶段的可达备用点：在预测位置和载荷下，剩余能源是否足以到达经过批准且当时可用的基地/备降点，并满足相应储备。

这依赖备用点、天气、路径和设备能力；无可信信息时不能给出通用“安全返航”承诺。选择备用点要同时考虑投送物资仍在机上，不把其当空载。

## 4. 天气模块：从信息接入到真实影响分三级

### W1 信息与作业阈值

支持手工输入情景和已配置预报源；各变量保留来源、发布时间、适用时间、空间分辨率和高度。地图/任务条展示风速、阵风、方向、降水、温度等已存在数据；实时观测与预报不能混写。

依据机型/组织明确规则做作业窗口检查。缺少规则来源的通用告警不是硬性飞行限值。预报数据过期、区域不覆盖、飞行高度不匹配，应标出，不把它们当作已经评估通过。

Open-Meteo 可以作为开发期可替换预报适配器，但其免费托管服务用途条件与数据许可并非一回事；应核对实际部署用途。地图格点预报不能替代局地实测。[S17]

### W2 时间与能量计算

仅当飞行速度定义和机型模型允许时，将风转换为顺/逆/侧风分量，影响航段可达性及持续时间。气象风向通常是“风从哪里来”，可视化箭头往往指“吹向哪里”，必须在 Adapter 中统一转换并测试。

例如，在“水平、稳定风、固定真空速、保持给定地面航迹”的简化假设下，沿航迹地速可写为：

`v_ground = sqrt(v_air² − w_cross²) + w_along`

必须满足 `abs(w_cross) <= v_air` 且 `v_ground > 0`，还需考虑机型其它限制。该式不自动适用于已经把速度定义为恒定地速的原数模模型，也不能提供真实功率模型。能量应由兼容模型的功率—时间或标定关系计算，不对旧能耗随意乘一个无来源风系数。

路径上的风随位置、高度、时间变化时，分段计算并记录插值与适用范围；不以起飞点一个小时的风代表整条任务。

### W3 不确定性与稳健比较

只有在已说明的误差场景或经校准分布下做情景优化/风险统计。人为设置“能耗增加 5%、10%”是压力实验，不是事件发生概率。显示某场景集合中的未完成/超阈值比例，应注明模拟试验含义，不能称为实际坠机概率。

历史在线实验只能使用当时已发布的信息。不能让某算法提前看到未来天气或未来需求，再和只能看到当前信息的在线算法公平比较。保存 forecast issued_at 或当时下载的快照；不能用事后观测回填决策输入却不说明。[S17]

## 5. 地形、空域与机间冲突

### 5.1 路径不是地图上一条美化曲线

算法提供真实候选路径和三维分阶段高度。前端不得为美观改动路线几何、停靠顺序或高程。路径缓存要绑定地图、限制区、设备模型与约束版本；事件变化后只复用仍适用部分。

二维图层相交只是检查入口：有高度/生效时段的限制区应检查三维/时间关系；未知高度限制按明确保守策略处理，不能默认为无限高或没有限制而不说明。

### 5.2 DEM 不等于全部障碍

原题 30 米 DEM 不能凭空表示细小树木、建筑或线缆。数据有缺测/垂直参考不明时，不能靠渲染出来的漂亮山体认证净空。导入不同地区时重新选择合适米制投影，避免固定原题坐标配置。

### 5.3 机间冲突不能只比较平面交叉

两条线在平面交叉但不同时经过，不一定冲突；平面不交叉但三维距离/时间接近，也可能触及分离规则。建议先对候选连续分段轨迹进行时空相邻筛选，再检查距离与相应阶段缓冲。资源占用中的起降位同样受时间约束。

分离距离、时间缓冲和不确定带要按模型与运行规则配置，不能设一个通用数字就声称适用于所有真实设备。若仅做离散采样，明确分辨率和未能证明的区间；不能把采样无冲突写成连续保证。

## 6. 在途修复：从“删掉一架未起飞机”升级

按执行状态分层支持：

| 状态          | 可以自动调整什么                                             | 不能做什么                         |
| ------------- | ------------------------------------------------------------ | ---------------------------------- |
| 尚未预约/装载 | 重新组批、改机、换电池、起飞时间                             | 不能使用不可用库存                 |
| 已预约未装载  | 在明确取消预约后调整                                         | 不得双重预约                       |
| 已装载未起飞  | 同机变更；必要时安排有耗时的卸载/重装                        | 不得瞬间把货箱移回仓库             |
| 在飞          | 在可信实况与设备能力下改变后续可控航段/任务；或先保持已承诺段 | 不得换电池、换载机、重置满电或起点 |
| 到站交接中    | 保留已完成交付；调整剩余部分需真实操作规则                   | 不得撤销已经交付箱件               |
| 已返航充电    | 分离机体可用时刻与电池释放                                   | 不得把返航等同电池可再用           |
| 失联/位置未知 | 记录、限制自动改派范围、请求人工处置与后续核对               | 不得把未知设备当作已落地空闲       |

每个模式都有最小数据门槛。界面“中途修改”必须提供受影响计划预览和用户确认；直接点击地图拖动在飞机体到新位置不属于合法执行事实。

## 7. 三个主创新：从卡片说明变为可操作能力

以下是**建议研究与产品特色**，不是已证明的新颖性或效果。联合运输/通信、学习辅助邻域、风风险返航已有相关研究；近年的相关预印本还在扩展相近问题。[S24—S26] 最终参赛论证要强调本项目的具体约束组合、方法和实验，而不是宣称“首次把 AI 用于无人机救援”。

### I1 条件变化驱动的方案有效性检查

**场景**：计划计算完成后，天气快照更新、投送点关闭或一块电池电量下降，旧计划还在页面显示“已验证”。

**方法**：给计划建立依赖与有效区间；变化事件命中相关设备/地图/时间段，定位受影响架次与约束，重新评估或修复。不是每秒把全部规划作废，也不是计算一次就永久有效。

**用户看到**：某条航段/架次出现“需重查：风况更新”，点击看到当前与旧条件、受影响物资和可采取动作。未受影响的任务保留原确认状态。

**实验**：对比全量周期重查、仅直接对象更新、依赖感知更新；比较检测覆盖、处理耗时、漏报/误报（在标注模型事件下）、不必要的重排量。有效性指纹是可追溯依据，不是实飞安全证书。

### I2 执行承诺约束下的资源依赖局部修复

**场景**：电池或中继窗口变化会影响多台无人机的后续任务，全量重算容易打乱已协调安排。

**方法**：任务—机体—电池—充电口—中继窗口依赖图；冻结已发生事实与不可立即撤销的任务；沿未来依赖扩展邻域，先局部修复，必要时扩大或全量回退。目标中区分改机、改时间、重新装卸和中继变动代价；硬可行性优先于稳定性偏好。

**用户看到**：事件后“影响 4 个后续架次，保留 7 个安排”等真实计算摘要，地图与资源轴显示传播链及前后差异。不能硬编码这些数字。

**实验**：相同模型、预算、线程、事件可见信息下对比全量重算、固定半径局部修复、依赖传播、去掉稳定性代价等。报告首个验证可行解时间、保障缺口、变更数和实际目标值，不只给平均速度。

### I3 可计算的资源增配与取舍建议

**场景**：任务无法全部按期完成时，用户不知道加一架机、一块电池还是一个充电口更有用。

**方法**：识别候选瓶颈，构造增配/放宽非关键时限等独立反事实场景，真实重求解，输出受益需求与资源代价。允许组合资源建议，避免只看一项容量忽略瓶颈转移。

**用户看到**：建议表中每个选项的额外资源、保障变化、时间/能量变化、求解预算与证据；点击某项在地图和时间轴对比。

**实验**：验证建议在对应场景下可行，对比启发式“统一加机”与逐类增配；有小实例精确解时检验最小增配。有有限搜索时只称“当前预算内找到的建议”，不称全局最少。

额外资源不应让理论最优变差，但不同有限搜索可能产生更差候选。应保留仍可行的原方案作为基线，区分搜索结果与最优响应，不能用非单调启发式结果推出资源越多越差。

## 8. AI 的明确位置：辅助搜索，不代替物理和权限

优先采用轻量监督学习/排序或上下文选择模型，学习在何种任务与资源状态下选择哪类邻域算子，而不是让语言模型直接生成可下发航线。

输入可以包括需求紧急度、时间窗紧度、资源瓶颈、能源/通信余量、事件类型、近期算子改进。标签来自真实搜索日志，包括改进量、可行候选比例和耗时；拒绝只用规则生成标签再宣称学到了新规律。

训练/验证/测试按完整场景、地图或事件序列隔离，不把同一个任务实例的相邻步骤随机拆成训练与测试。对比随机选算子、固定规则、非学习自适应选择和学习选择；相同预算，报告训练开销与推理开销。[S24]

模型缺失或失效时回退到已验证的非学习选择器。所有候选继续进入同一独立检查器。预测质量和能力单独登记，没有训练记录时 UI 不显示“AI 已优化”。

AI 可以生成用户可读解释草稿，但解释的数值和原因必须引用结构化结果。不得让解释模型替用户批准真实下发，也不得自由调用飞控控制工具。

## 9. 目标函数与服务优先级

先满足物理、设备、资源和强制保障约束，再优化时效、能源、费用或均衡。不能让“费用优先”通过少送关键物资得到貌似更优的方案。

资源不足时明确输出部分保障建议与缺口，按照用户批准的保障优先规则处理；必要的核心需求是否放宽，不能由算法悄悄决定。基本保障建议以每个站点所需组合为依据，不把“送到任意一箱”视为整站已保障。

费用必须由费率配置生成，能耗不自动换成人民币。均衡指标、归一化基准、参数和约束在同次比较中固定；几个离散候选只能称候选非支配集，不宣称完整帕累托前沿。

## 10. 评测：每个创新都要能被关掉作对照

### 10.1 评测数据

- 原题数据：模型回归与论文结果口径核对，不是新系统实测性能。
- 合成多区域、多规模、动态事件：算法研究和系统压力；标记合成来源。
- 人工配置演练：可用性与现场流程验证。
- 已授权实测日志：设备标定和现实适用性；没有时不伪造。

保留完整输入、地图/气象/模型版本、事件序列、种子、预算、线程与 commit。不能仅保存几张漂亮结果图。

### 10.2 基线与消融

B0 最早截止的可行贪心；B1 原静态算法；B2 同预算全量重算；B3 非学习局部修复；B4 依赖传播+稳定性约束；B5 学习辅助完整方法。按实验目标选择可比集合，不为了表格完整强行比较不同约束、不同未来信息或不同交付计时的结果。

消融至少涉及：不做依赖传播、不做变更惩罚、不做气象更新、固定余量与情景模型、规则与学习选择、通信顺序规划与联合规划。一次实验只回答一个主要贡献问题。

### 10.3 指标

| 维度      | 指标                                                     |
| --------- | -------------------------------------------------------- |
| 保障      | 必须需求按期数量、未满足量、各点基本保障时间、加权延期   |
| 调度      | 最后交付、最后返航、运输/中继架次、资源峰值与等待        |
| 能源/资源 | 总能耗、最小返航余量、充电等待、增配数量、已配置费用     |
| 在线响应  | 第一个验证可行解用时、重规划 p50/p95、预处理/校验耗时    |
| 稳定性    | 改派架次、起飞时刻变化、重新装卸数量、撤销承诺量         |
| 可靠性    | 约束违反、未找到可行解、超时、过期数据使用、事件重复应用 |
| 可用性    | 新用户建任务用时、完成率、误操作、找不到下一步的次数     |

成功场景和失败场景分别报告，不能剔除全部失败后只算成功样本平均耗时。固定硬件与软件环境；预热缓存、冷启动、预处理是否计入都注明。未实测前不在界面/材料写“秒级”“提升 30%”“100% 可靠”。

## 11. 增加但不阻塞主业务的扩展

照片建图走 ODM 等独立异步服务，上传—处理—质量确认—资产入库，不与求解接口同步等待。[S15] 地图显示、照片测绘、飞控执行是不同能力。

多基地和移动补能、多机构权限、现场移动端上报纳入任务板，不能只增加配置字段却继续使用单基地假设。先完成数据模型、当前位置、运输/补能逻辑和独立检查，再启用菜单。

本轮首要交付仍是：完整新任务流程、正确地图与方案分析、可持久化模拟执行、真实事件驱动修复、资源解释，以及经过测试的设备适配边界。外部能力缺失时推进其它可完成项，并准确记录阻塞，不再用大段页面免责声明代替功能设计。
