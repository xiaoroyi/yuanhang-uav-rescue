# 援航 V2｜任务流程、地图工作台与执行闭环重构包

版本：2.0（设计与实施规范）  
编制日期：2026-10-18  
适用对象：已有援航仓库上的增量重构；不是新的空白项目脚手架。

## 先读这段

本包依据用户提供的六张初版截图、既有开发总纲/接口细则、原数模论文与题目，并结合公开产品文档及研究资料编制。**没有读取或运行当前 GitHub 仓库，不能据此认定已有按钮、算法或接口真的失效。**截图支持的是界面问题；源码现状、真实能力、已通过测试要由 Codex 在仓库审计后记录。

重构的核心不是增加装饰，而是让普通用户沿着“首页 → 新建救援任务 → 条件检查 → 生成与比较方案 → 演练/执行跟踪 → 调整与复盘”完成业务。已有可用算法、数据、接口和验证器应保留。顶层导航、工作台布局、地图交互、结果解释与执行状态需要系统重构。

## 文件与使用顺序

1. `docs/01_PRODUCT_UX_SPEC.md`：截图诊断、导航、逐页设计、文案与视觉尺寸。
2. `docs/02_MAP_ANALYTICS_SPEC.md`：地图数据、交互、动态图层、数模分析图到产品的映射。
3. `docs/03_CONTRACTS_EXECUTION_SPEC.md`：现有接口兼容、新对象、算法—后端—前端数据流、遥测和指令。
4. `docs/04_ALGORITHM_REALISM_SPEC.md`：现实约束、天气、电池、在途修复、创新与评测。
5. `docs/05_TASKS_ACCEPTANCE.md`：全部任务、依赖、验收、旧功能追踪与交付证据；不按日期排期。
6. `docs/06_RESEARCH_NOTES.md`：所给四个参考及成熟系统、技术文档、论文的来源与借鉴边界。
7. `prompts/CODEX_REDESIGN_EXECUTE.md`：一次提交给 Codex 的执行提示词。
8. `evidence/current-ui/`：用户提供的六张重构前截图，只作为界面审计依据。

仓库放置建议：整个目录放到 `docs/redesign-v2/`，不要覆盖仓库已有根级 `AGENTS.md` 或 `contracts/`。首次执行时由 Codex依据本包更新任务板、决策和兼容迁移计划。

## 文档优先关系

- 用户本次批准的产品方向优先于旧版“三页工作台”和“数据大屏首页”的建议；其余旧功能不得静默删去。
- 已运行机器契约仍是当前事实。本文新增字段是待实现的目标契约，不是已存在接口；不能用 `any` 或放开所有额外字段绕过迁移。
- 先审计后映射：如果现有文件名、框架或 API 与示例不同，保持现有合理架构，不为匹配文档路径重写整站。
- 本包数字化尺寸、测试预算和合成场景属于设计/验收目标；不是实际性能结论。
- “已验证”仅表示指定输入及模型范围内检查通过，不能替代现场许可、机型适配、飞控保护或专业操作。

## 本轮完成标准

必须交付可运行的软件变更与证据，不只提交新计划或静态原型。首页、任务准备、检查、计算、结果、模拟执行、事件调整、复盘应贯通。所有页面里的主要动作必须有真实服务路径、禁用原因或明确外部依赖状态。

仿真、飞控软件在环和真实设备分别登记能力。没有真实硬件时，仍应交付适配器接口、指令生命周期、遥测流、契约测试和可运行的仿真适配器；不得显示“真机接入已完成”。
