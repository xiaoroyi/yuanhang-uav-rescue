# RFC-009 单点额定运输能力与整箱组批诊断

状态：implementation-branch，用户授权实施，待A/B正式复核。不改变Plan、Scenario或Snapshot字段，不将诊断批次伪装成实体调度方案。

新增只读GET /api/v1/snapshots/{snapshot_id}/single-site-analysis，可选min_return_soc为诊断参数，默认原快照策略值。前端在场景页按用户点击创建不可变Snapshot后分析；切换诊断余量不修改场景策略。报告保存snapshot_id/content_hash、分析参数、派生分析hash和模型边界，实际OpenAPI统一生成TS。

模型single_site_nominal_transport_v1对应原题Q1：每批仅服务一个站点，机型按其reference_energy_kwh作为额定满电、SOH=100%的能源，不考虑实体机体/电池数量、充电、并发、时限或通信。地形和静态限制区沿用当前物理/路径模型。额定载荷能力不是实际机队的可执行许可。

各站各机型通过单调能耗边界二分得到最大安全质量，体积约束单独显示并参与整箱组批，不用未知密度把体积换算为质量。空载往返即超过余量时返回null与原因，不把零伪装成可达。

将同站、同物资类型、质量和体积完全相同的箱件归为计数类，枚举计数向量与全部声明机型，再以有限动态规划按“最少架次 → 最小运输能耗 → 最小累计作业时间”排序。仅在这些物理属性可交换、供需清单完整一致的条件下声明该有限模型的最少架次数。第一版每站最多512个计数状态；库存选择有歧义或规模超限时明确partial/limited，不假称全局最优。

报告包含每批type_id、真实cargo_ids、质量/体积、准备到返航的累计作业时间、能耗、额定返航SOC及独立物理复算结果。没有drone_id、battery_id或实际起飞时刻。独立检查重新从箱件、两条航段和模型参数计算，不信任优化器的passed标志。还提供逐箱直送与确定性贪心合并基线，以及余量变化的有限对照；不将Q1累计时长当作Q2完成时间。

结果complete仅表示声明的额定单点模型完整求解与检查，partial表示部分站点/输入条件未满足，limited表示当前诊断不支持；均不等于Plan.has_validated_plan。普通真实调度仍须通过solve和完整约束检查后才能确认。
