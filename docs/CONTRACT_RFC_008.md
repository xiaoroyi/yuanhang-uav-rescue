# RFC-008 本机启动与版本身份

状态：implementation-branch，用户授权实施，待A/B正式复核。不改变Scenario、Snapshot、Plan或求解语义。

Health响应兼容增加service_source_sha256和runtime_id，分别表示本服务进程启动时的业务源码身份与数据目录身份，不返回数据目录原始路径。原service_id、workspace_id、service_version、status、solver_ready保留。更新实际OpenAPI和生成TS，不手写第二套HTTP字段。

启动器只复用同一项目、同一数据目录、相同业务源码身份的健康服务。检测到本项目旧服务时说明需要停止旧窗口并重启，不终止未知进程、不把旧后端当作新版本打开。其他项目或其他数据目录占端口时明确拒绝复用。

前端构建记录源码hash、构建时间、Node版本和全部产物校验值。启动时检查源码/产物一致性；已有产物有效时不依赖Node或网络，过期时只使用项目已安装依赖离线重建，不隐式安装或更改全局环境。缺少构建条件时给出安装命令，不能静默启动白屏版本。

源码身份排除运行数据、日志、缓存与证据，避免普通计算让服务被误判为过期。前端Python启动器和Node构建工具使用同一哈希序列约定并进行一致性回归。验证报告记录测试前后源码身份，发生源代码变化时不能把结果标为同一代码版本的完整通过。

本轮同时完善Windows安装入口，识别已有项目环境、Python3.11/3.12及PATH中的兼容Python；普通检测不安装依赖。运行依赖仍在仓库.venv与frontend/node_modules中。
