# RFC-007 冻结联合方案的分区与资源配置

状态：implementation-branch，按单人全栈授权实施，待A/B正式复核。此扩展不改变Scenario、Snapshot或Plan，不改写既有方案的实体ID、时间或通信来源。

新增只读`GET /api/v1/plans/{plan_id}/partition`，响应PartitionReport，实际Pydantic/OpenAPI/TypeScript共同生成。输入始终是该Plan绑定的不可变Snapshot，不能拿当前场景版本代替。联合方案须经独立检查；未包含连续通信范围、存在执行事实、异质能源状态或超出有限枚举规模时返回明确limited状态及原因，不返回伪造分区。

任务冻结：逐箱组批、运输访问顺序、全部准备/起飞/交付/返航/释放/充电时刻、中继驻点及服务窗口、通信报告实际来源均保持不变。允许物理相同、初始可用条件相同的实体重新编号并划为各组专用资源。不能把这种资源重新编号解释为保持原实体ID不变，更不能解释为重新联合优化。

同一运输架次访问的站点不可拆分；同一中继任务实际保障的所有运输架次及其站点不可拆分。由这些超边形成连通单元，再完整枚举2个、3个非空组的无标号划分。每个站点恰属一组，每个运输/中继任务恰属一组，每条通信来源关系不得跨组。零任务站点仍保留在站点集合中。第一版最多10个连通单元，超过时仅说明有限规模限制，不称不存在合法分区。

按左闭右开区间扫描机体、运输电池、中继机、能源组件的资源峰值。电池占用含排队及实际两阶段充电，机体占用含独立周转。有限地面容量启用时，另计算各组准备工位和充电端口峰值；不允许把跨组共享地面容量隐含为免费资源。输出峰值时刻及任务见证，区间着色生成组内专用逻辑资源编号，并核查同一编号不重叠。

当前精确资源计数只适用于各类实际可用实体均从零时刻在基地、运输电池/中继组件初始满SOC且同类型可用容量相同的输入。不同健康度、初始可用时刻或初始补能不套用同质资源峰值定理；保留原方案供用户查看并解释不支持原因。

报告记录plan_id、snapshot_id、scenario_state_version、snapshot_content_hash、source_plan_hash、原子单元及连通边、资源类别与库存、联合共享池峰值。每个K给出候选数量、资源优先与均衡优先的具体方案、组内站点/任务/工作量/资源峰值、总配置、相对共享池增量、相对库存缺口、闲置库存，以及工作量CV²。

HTTP的source_plan_hash针对GET Plan的JSON表示计算，先按同一Pydantic类型规范化UTC日期；CLI针对其输入Plan JSON计算。使用shared.contracts.content_hash核对，避免+00:00/Z的存储与HTTP表示差异。

资源优先的字典序为：归一化库存缺口、归一化总资源量、工作量CV²；均衡优先则先CV²，再前两项。各类归一化分母为max(1,可用库存)，避免零库存除法。工作量定义为运输与中继从准备到返航的累计秒数，不混入充电等待或周转。排序使用十进制时间和有理数，不通过浮点四舍五入制造平局。输出的精确性仅针对冻结任务及上述有限划分空间，不证明可重组批/改时刻情况下最少资源。

前端在事件复盘提供独立分区面板，显示冻结来源、不可拆分关系、2/3组选择、资源配置和共享损失，并可导出完整JSON。资源不足要明确显示需要补充的类别与数量；未进行新资源联合重算时不得声称当前库存已可独立执行。独立核查包括双重连通性重建、任务/站点唯一归属、通信来源归属、区间着色不重叠与峰值下界见证。
