# G0 规范初始化报告

本文记录最初G0阶段的历史检查与待批事项。之后用户已授权并完成大量分支实现；当前能力、运行命令和验收以[真实实现状态](IMPLEMENTATION_STATUS.md)及[全栈交接](SOLO_DELIVERY.md)为准。不要将下文历史“不实现业务系统”作为后续任务的停止指令。

目标：让没有聊天记忆的 A/B 两位成员及其 Codex 从仓库获得统一需求、职责、接口、任务和验收依据。本轮不实现业务系统。

## 已整理的结果

- 新建根和三个模块 AGENTS、README、Git协作规则、PR模板、CODEOWNERS、编辑/换行约定、忽略规则、契约CI。
- 适配原ZIP的13份Markdown为两人规范；增加B的统一系统入口。C-*后端任务仍保留，owner均B；原ZIP完整留档。
- 建立数据、HTTP、Solver接口草案、RFC-001、决定日志、契约版本记录与真实实现状态。
- 建立56项无日期任务板：G0 7项、G1 9项、G2 5项、G3 5项、G4 14项、G5 7项、G6 9项。部分含糊阶段依赖已展开为无环任务依赖，C-09/B-09分列；P1/P2全部保留。
- 新建10份Schema、12份Mock样例、16项HTTP操作草案。样例不包含伪造的真实成功结果。
- 归档42份必要原件，约30.33MiB，含开发方案、讨论、ZIP、原题、论文/答案、18份源码、5份输入表、DEM及正式发布依据。未动外部原件，无整库/依赖环境复制。

## 发现的关键差异

1. 对接包引用的早期V1 Schema/fixtures根本不在本仓库或本次ZIP；无法复现它声称的早期校验。本轮为新建0.1.0-draft，不宣称兼容未取得V1。
2. 用户实际两人，原文三人；全部活动规范已适配，原文只留references。
3. Word和ZIP在路由、事件字段、箱件字段、成功/验证失败组合上不同，RFC-001明确选项。
4. 动态执行事实、中继实体、部分保障、地形资产及费用模型不完整；保持后续RFC与任务，不私自假装P0已支持。
5. 原数模多代结果共存，以20260926_v4_excel1为主，正式论文/答案hash一致。旧代码存在sys.path/目录副作用、硬编码与输出依赖；未执行旧搜索，不声称跑通。
6. 论文原件包含实名信息，submission需独立匿名构建。比赛指南与最新通知未在本轮独立核验。

规则与可审查草案已产出，**G0 Gate仍为awaiting_review**。G0-03/04待共同冻结与实现阶段生成验证；G0-05已完成静态与依赖就绪性诊断，真正适配运行属于A-01；G0-07需远程CI实际执行。不会为了“完成”把这些改成done。
