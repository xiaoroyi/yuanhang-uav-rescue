# RFC-006 连续通信与中继协同

状态：implementation-branch，用户授权实施，待A/B正式复核。保留旧Scenario/Plan缺省字段及hash；不改变旧运输指标含义。

Scenario可选communication，明确projected_dem_radio_v1传播参数、双向终端参数、固定网关天线高度、一种中继机物理模型、实体中继机与可更换能源组件、有限候选悬停点。policy.requires_communication启用必检；缺少配置/DEM或超出模型支持范围返回UNKNOWN，不退回运输方案冒充联合可行。

采用基地所在UTM带的冻结投影DEM闭四边形，像元边数值外扩2毫米；运动为测地航路按最多250米分段后的投影直线弦，时间保留爬升/巡航/下降/交接。对整个连续阶段解析计算球面距离阈值及扫掠视线遮挡区间，包括孤立边界接触；不是按固定秒取样。NoData作为不能依靠视距排除的障碍，超出DEM/100km本地域拒绝。它是声明的有限几何与题设链路损耗模型，不是实际无线电可用性认证，不含天气、衍射、频谱占用或真实覆盖测量。

Plan可选relay_sorties记录中继实体、能源组件、悬停坐标/高程、准备/起飞/到达/建链/服务/返航/周转/充电全过程，采用原题两阶段充电和独立能源组件SOC。准备工位与充电端口在启用有限容量时由运输和中继共同竞争。中继间不转发；服务时须同时满足接入和固定网关回传。

Plan可选joint_metrics记录relay_energy_kwh、joint_energy_kwh、joint_makespan_s、relay_sortie_count；既有metrics继续仅统计运输，以保持旧消费者含义。联合求解目标使用共同加权延期优先，再比较联合时间/能耗/均衡目标。通信报告包含完整运输活动时长、直连/中继时长、缺口与服务窗口；独立检查重建物理和链路，不信任报告passed标志。

第一版联合求解是有限运输组批/访问顺序与有限悬停位置上的分解调度：先生成运输候选，再联合调整开始时刻与两类实体资源。未找到解只表示当前分解/候选/预算内未找到，不能称原问题不可行。只支持初始满SOC、基地未执行状态；动态机体故障采用完整联合重算，暂不承诺局部保留中继方案或执行中调度。

本RFC必须与生成类型、独立负例、后端任务、地图/时间轴、指标和导出共同落地，未接通前capabilities不宣称relay_coordination已可用。

实现补充：joint_search在Plan及无解SolverOutcome中可选提供，用于保存有限候选数量和各阶段状态；缺省旧Outcome不追加该字段。独立校验失败返回ERROR/validation_failed，不能降格为普通UNKNOWN；继承基线的first_feasible_s记录重新验证基线的时刻。CLI使用实际UTC创建时间和唯一ID。
