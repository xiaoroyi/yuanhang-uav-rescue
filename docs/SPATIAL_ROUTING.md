# 静态限制区与真实绕行

场景与资源右侧“管理限制区”可添加经纬度矩形、编辑多边形JSON，或导入GeoJSON Polygon/Feature/FeatureCollection。导入先替换草稿，保存才创建新场景版本。最多12区、每环64点、合计160顶点；单外环闭合，不接受自交、孔洞或MultiPolygon。buffer_m范围0–5000米。

`local_polygon_v1`使用基地中心WGS84等距方位投影解释多边形和米制缓冲，端点及顶点限于基地100km内。可见图以禁区缓冲外再加10米的顶点生成候选，最终测地航段以20米弦复查禁区相交。边界与缓冲均禁入。基地/服务点位于禁区或有限图未找到可认证路径，返回UNKNOWN/input_not_ready；不伪称证明整个问题无解。

physics.Leg保存真实绕行点和累计WGS84距离，沿全部折线查询DEM闭像元最大高程，按该航段统一巡航高度重算爬升、载荷能耗和飞行时间。独立验证重建规定路径、时间及能耗，并检查实际提交折线的禁区相交。回放按各折线段长度分配计划飞行时段，是位置示意，不是飞控轨迹或遥测。

地图/打印报告显示原始禁区边界；求解另含设定缓冲和数值余量，不把显示边界当作缓冲后的真实禁入边界。路线与区块来自绑定快照，旧方案仍使用原快照；新保存的禁区使旧方案无法确认，重新求解才绑定新约束。

缓存键含基地、完整区域内容和航段端点；版本/hash包含完整限制区，区域改动不复用旧候选。入库和HTTP省略未设置的扩展字段，旧Snapshot无此字段时hash原样保留。Excel模板将限制区存于scenario工作表的JSON列，预览再按同Schema校验。

证据：`evidence/solver/zone-compact.json`是真实32箱场景的一次限时运行；`tests/solver/test_routing.py`覆盖能耗路径、绕行、穿越造假、无效区、禁区端点/缓冲/边界和区域范围；`tests/backend/test_spatial.py`覆盖旧快照及Excel往返；浏览器实测见`evidence/browser/verified/zone-*.png`。这不涵盖动态生效区、三维障碍、天气、空管许可、全航程多机避碰。
