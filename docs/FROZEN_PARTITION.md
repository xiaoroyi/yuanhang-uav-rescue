# 冻结联合方案的任务分区

入口：生成包含通信范围的已验证方案，在“事件复盘 → 冻结任务分区”查看。可切换2/3组、资源优先/均衡优先，展开各组的峰值任务与专用实体分配，下载完整JSON。没有联合方案时明确提示先配置通信并重新计算。

## 固定什么、允许改变什么

完全继承绑定Snapshot中的运输组批、访问顺序、准备/起飞/交付/返航/释放/充电时刻，中继驻点/服务窗口，以及独立通信报告的实际来源。不能重新排程、把一个中继任务复制给不同组，或使用当前场景新版本替换历史输入。

同一运输架次访问的服务区必须同组；同一个中继任务实际保障的运输任务及对应服务区也必须同组。先用并查集合并，另用二分图洪泛核对连通单元，再完整枚举无标号的2/3个非空组。每个服务区、运输任务和中继任务只能归属一组。没有实际服务对象的中继任务不能被静默删除，第一版会说明其归属条件未满足。

允许同型、同可用容量且初始条件一致的资源重新编号，各组独占这些实体。原Plan的ID与全部物理记录保持不变，分区报告单独列出原实体和分配后的实体。库存以外的资源标记为ADD与“需增配”，不自动加入场景，不冒充已经拥有的资源。

## 资源、工作量与排序

资源区间左闭右开，结束与开始时刻相等时可立即重用。机体区间包含准备、飞行、交接及自身周转；电池/中继能源区间包含从准备开始到补能结束的全部占用。等待充电占用能源资源，不占用充电端口。启用有限地面模型时，准备工位和充电端口也分组独立核算。

对每类资源扫描并发峰值，并输出达到峰值的具体时刻和任务集合。区间贪心着色构造达到该峰值的实体分配，再独立检查全部任务、时间、唯一归属、跨组共享和重叠。由于资源同质，峰值是**冻结区间下**所需数量；不意味着重新组批/调时刻时的最少数量。

总配置为各组峰值之和。共享损失=总配置−全局共享池峰值；库存缺口=max(0,总配置−可用库存)；未分配库存=max(0,可用库存−总配置)。工作量为准备开始到返航的累计秒数，包含运输与中继，排除充电及机体周转；并行任务累计工作量不等于墙钟完成时间。

资源优先按“归一化缺口 → 归一化总配置 → 工作量CV²”排序；均衡优先按“工作量CV² → 归一化缺口 → 归一化总配置”排序。归一化分母为max(1,该类可用库存)。计算使用Decimal时刻和Fraction排序，报告保留精确分数及显示值，避免浮点舍入改变排名。

## 当前边界

最多10个连通单元，超过时返回limited，不能解释为无合法划分。支持基地零时刻可用、初始满SOC且同类可用容量相同的资源；不同健康度/容量、初始补能或非零可用时刻不套用同质峰值结论。若原子单元少于要求组数，会明确说明保持冻结关系时无法拆分。未来动态执行事实和重新排程属于其他模型。

HTTP：GET /api/v1/plans/{plan_id}/partition。只读、不创建新任务或修改场景。后端读取该Plan绑定的Snapshot并独立复算联合方案后分析，历史场景变更不会改动分析结果。数据类型来自实际OpenAPI统一生成；兼容与边界见RFC-007。

HTTP报告的source_plan_hash按GET Plan的JSON表示计算，统一UTC时间序列化，避免数据库中的+00:00与HTTP中的Z造成格式差异。可用shared.contracts.content_hash对下载的Plan JSON核对；CLI则对其输入Plan JSON计算同一规范hash。
