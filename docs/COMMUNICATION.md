# 连续通信与中继联合调度

在场景与资源页打开“配置通信资源”，检查链路参数、中继机和能源组件，然后开启“要求全程连续通信”并保存。需要已绑定DEM。场景产生新版本；重新求解将启动真实联合Worker。界面给联合任务60秒预算，支持取消与刷新恢复；原运输模式继续使用15秒快速预算。

默认参数取自只读归档的通信链路参数.xlsx与中继无人机数据.xlsx：2400MHz，系统损耗3dB、遮挡附加10dB、灵敏度−98dBm、衰落裕量8dB，固定网关天线离地20m。由双向收发预算得到直连/接入/回传门限122/116/126dB。原题有2架中继机、6个3.2kWh能源组件；中继质量23.5kg、巡航15m/s、悬停1.05kW、通信附加0.05kW、返航储备20%。表单可改变参数或资源状态，其他资源和候选位置可编辑高级JSON；保存由统一Schema和引用检查约束。

## 几何与传播范围

`projected_dem_radio_v1`使用基地所在UTM带，支持纬度−80至84度及基地100km内的端点。绑定DEM冻结为投影闭四边形像元，边长最多1000m并限制投影角度失真；像元边向外增加2mm数值余量。按像元包围盒层次保守筛选扫掠三角形候选，不用逆投影取样剔除像元。视线扫掠范围超出DEM时拒绝检查，NoData不能作为已知无遮挡区使用。

运输运动保留爬升、巡航、下降、交接阶段。WGS84航路按最多250m分段，通信模型在各段使用连续投影直线弦，并按对应飞行时间移动。通过距离二次方程的阈值交点、扫掠视线三角形与闭像元/高度半空间的裁剪，求全部可用与不可用区间，也保留孤立接触事件。边界另做微小时间外扩。回传在中继固定悬停点检查；直连失效时须有同一时刻可用的中继接入和回传。中继之间不转发。

这是声明的有限几何与题设损耗模型。它没有声称测地运动/弯曲像元边界的无限精度证明，也不是现场无线电覆盖认证；风雨、衍射、频谱拥塞与实际设备可靠性尚未建模。地图紫色点线表示网关回传，不能解释为圆形覆盖区域。

## 任务与资源

中继任务包含准备、出发、到达、建链、悬停服务、返航、机体周转、能源组件补能。飞行净空和静态限制区真实参与路线与能耗计算。悬停高度取DEM地面高程加AGL，受模型上限约束。服务能耗包括建链至服务结束的悬停与通信耗能，飞行阶段使用题设巡航与爬升能耗；下降不另计附加能耗。

中继机和能源组件分开预约，充电使用题设两阶段模型。启用resource_limits后，运输和中继共同竞争准备工位与充电端口；确认在同一事务记录两类实体及逻辑地面资源。组件占用含排队，机体返航周转后即可释放。相同物理能力的中继资源使用容量约束，再按区间分配真实实体ID；不同可用时刻先表示为占用前缀，容量/SOH不同的能源组件仍显式选择，独立检查继续逐实体验算。当前联合求解只使用基地可用、初始满SOC资源；运输低SOC输入会明确报告当前联合模型不支持，不能偷偷补电或重置状态。执行中事实仍未开放；运输机或中继机零时刻故障采用完整联合重算。

## 求解与独立检查

先为私有运输松弛生成箱件组批、访问顺序和机型，再在固定这些模式及有限悬停候选上联合调整开始时刻、运输机/电池、中继机/能源组件、服务窗口。私有松弛有独立ID，不保存为用户联合方案。几何覆盖需求在连续有效范围内合并，相同候选集合的连续原子最长60秒；不凭端点取样代替全过程覆盖。

原题15点模板另外保留历史提交中的3个高地驻点；候选上限仍为48。预算至少20秒且当前逐箱需求和站点归属匹配时，先尝试历史23组箱件与访问顺序，所有物理数据从当前输入重新计算。此候选族只选上述3个驻点、最多3个中继架次，将有共同驻点的覆盖区间保守合并至最多600秒：跨越直连区间时仍要求中继持续服务，因此只会收紧约束。失败后在剩余预算尝试一般启发式候选。模板不含历史时间、能耗、SOC、机体分配或验算标志，不能直接发布；来源hash记录在solver/data/contest_joint_patterns.json。改动箱重、机型、地形、时限、位置或资源后仍须重新排程并独立检查，不保证固定模板始终可行。

CP-SAT采用10ms保守时间包络，中继组件在搜索时使用全充电时长上界，输出和独立检查使用真实两阶段充电时长。先减少优先级加权期望延期，再比较联合时间、能耗或均衡目标；若第一阶段尚未找到方案，剩余预算继续搜索可行解。找到的联合方案还要重新从快照重建物理、载荷、时限、实体占用、地面并发和连续覆盖。删除中继、缩短窗口、篡改SOC/能耗或重复使用组件不能沿用passed标志。

只在上述有限分解中搜索，不能把有限CP的OPTIMAL称为原问题全局最优。UNKNOWN表示当前预算/候选内没有得到通过检查的方案，不等于资源必然不足或原问题不可行。联合深入优化继承有效基线，仅接受共同目标严格改善的方案。

## 指标与导出

旧`metrics`保持只统计运输，避免旧消费者悄悄改变含义。`joint_metrics`另给联合返航、运输加中继能耗及中继架次数；`relay_sorties`保留完整实体与时间记录，`communication_report`保留直连/中继来源窗口。累计通信时长按各运输任务累加，可能大于墙钟完成时间。结构化搜索证据在`joint_search`；不是设备遥测。

界面提供中继地图、资源时间轴与任务表；JSON保存完整记录，中继CSV单独下载，GeoJSON同时包含运输与中继路线，自包含打印报告保留联合指标和实体任务。场景Excel模板包含完整通信配置，导入往返已有回归。可用命令行复算：

```powershell
.venv\Scripts\python -m solver --example compact --communication --seconds 60 --output evidence/solver/joint-compact.json
```
