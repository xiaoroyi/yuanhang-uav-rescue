# RFC-003 静态限制区与旧快照兼容

状态：implementation-branch，待A/B团队复核。用户已授权本分支跨模块实现，不代替两人正式批准。

Scenario增加可选`restricted_zones`数组；缺省表示旧模型无指定限制区，不在旧对象中自动补null/空数组。每项为`zone_id`、`name`、`buffer_m`与单外环GeoJSON Polygon。坐标WGS84，闭环、无自交/孔洞，buffer_m为米、范围0–5000。最多12区、每环64点、合计160顶点。它是整个计划时域禁止穿越的水平区域（含边界与缓冲），不按高度/生效窗口放行。

所有端点和限制区顶点必须位于基地100km内。实现`local_polygon_v1`以基地为中心的WGS84等距方位投影解释多边形直边和缓冲，构造带额外10m数值余量的可见图；最终WGS84测地航段每20m细分后重新检查限制区及缓冲相交。未找到可认证路径返回UNKNOWN/input_not_ready，不伪称全局无解。路线长度、DEM净空、载荷能耗、飞行时长和回放都使用实际绕行折线。

非空限制区自动要求`restricted_zone`检查；相关model_scope/validation code枚举兼容增加该值。Plan原字段不变，LineString容纳绕行点。无区旧Plan、Snapshot及hash原样有效。新检查器重算规定路径，并重新检查提交折线与缓冲区相交，未评估不能发布。

为保持旧Snapshot身份，Pydantic规范化和HTTP输出使用exclude_unset，显式null仍保留；缺省扩展字段不写入旧对象。新增回归应包含旧快照往返相等及hash一致、新区快照绑定、穿越负例、错误多边形、边界接触、绕行能耗/时间和回放。

本扩展不实现飞行器间避碰、空管许可、三维障碍或实时区更新事件。旧客户端严格拒绝新字段时需与本Schema及生成类型一起升级；旧数据输入仍兼容。前后端及算法使用同一份Schema，不维护手写第二套类型。
