# RFC-031 · 保护执行实例与预约，禁止普通确认覆盖执行安排

2026-10-19 V3整体复核发现：P0时期的`POST /plans/{id}/confirm`尚未拦截已创建的V2模拟实例。直接确认一个方案会重建静态Reservation，尽管执行账本已有独立承诺。界面也仍显示可重复确认的按钮。

修复：场景关联的任务若存在ready/running/paused模拟实例，新确认请求返回现有`409 RESOURCE_CONFLICT`，提示进入执行调整或新建演练副本；在校验输入版本/快照后、改写预约前检查。已完成实例不阻断新的静态规划。完全相同幂等键/请求的旧回执仍按原合同返回，且不重放副作用。

前端对已确认方案、存在未结束实例的任务禁用普通确认，已确认状态直接显示。仍可查看历史、做独立方案试算；真实执行变化走既有事件/影响/修复/差异/采纳事务。Plan/Snapshot、执行事实、既有预约与旧回执不修改。不增加指令权限或真机能力。

按用户跨模块和状态/预约一致性授权修复；未代替团队批准。回归入口：`tests/backend/test_execution_confirmation_v3.py`。
