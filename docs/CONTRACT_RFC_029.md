# RFC-029：旧请求重试与修复派发幂等

验收修复中，不增加业务范围或HTTP字段。新增可空字段不得改变旧请求的有效重试：静态ExperimentRequest在repair_reference_id为空时兼容RFC025原哈希；ExecutionEventInput在weather为空时兼容旧原哈希；RepairRequest未提供repair_policy时或明确full时兼容RFC026之前的全量修复原哈希。新显式dependency不借旧全量回执解释为新算法请求；任何其它字段或owner改变仍409。保留原回执，不迁移/覆盖旧Plan、Snapshot或事件。

验收在隔离库复现：两个相同修复请求若在Job绑定间隙同时到达，旧实现会派发两个任务并产生回执唯一键错误。修复为输入/调整/幂等请求在同一SQLite事务提前持久接纳，然后派发Job并绑定；重复请求读取同一调整的当前投影，不再次派发。重启遇到已接纳但Job未绑定的记录，明确失败/派发未确定并保留原文，不盲重发，不永远computing。

对应兼容、并发、失败/重启用例与现有执行测试一起验证。首轮全量运行期间发现并修此问题，首轮源码变化必须如实记录；最终验收重新冻结并运行当前源码。
