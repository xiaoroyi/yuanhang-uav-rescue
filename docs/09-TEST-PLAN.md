# 测试与验收

所有阶段都区分结构检查、语义检查、物理验证、真实端到端。G0 通过结构检查不能替代其余三类。

## 当前实际可运行

1. `python scripts/check_contracts.py`：Schema 自检、样例校验、快照 hash、引用/身份、时间/资源基本不变量、状态组合、HTTP 草案引用。
2. `python -m unittest discover -s tests/contracts -v`：错误 SOC、坐标、额外字段、引用、重复箱件、资源冲突、版本/hash、成功状态伪造、Mock 误标、范围缺失等负例。
3. `python scripts/check_governance.py`：两人分工、任务 ID/依赖无环、完整任务板投影、资料 hash、旧源码 AST、相对文档链接。

生成负例是在内存中修改明确的开发样例，并非伪造算法成功数据。Schema 和语义检查不独立计算飞行能耗、DEM 净空、充电曲线或无线链路。

## 后续任务必须补齐的检查

| 阶段/任务 | 必须验收 | 证据 |
|---|---|---|
| A-01/A-02 | 非 Mock 小场景、单位转换、边界载重、逐段能耗、返航储备、独立重算 | 实际输入/输出、配置、命令、版本 |
| C-01/B-01 | Schema→Pydantic/TS、运行 OpenAPI、生成无漂移；JSON/CSV 映射及逐行错误 | 类型生成命令与 diff、API 测试 |
| C-02/C-03 | 快照不变、异步 Worker、真实 Job/Plan、取消/异常/硬超时/重启恢复、最小导出 | HTTP 请求响应与数据库测试 |
| X-01 | 新数据→真实算法→API→地图表格联动→导出 | SHA、快照 hash、实测用时、截图 |
| X-02 | 同快照 time/energy、机体/电池无重叠、费用 null、Mock/旧版本不可确认 | 原子确认与 UI/API 负例 |
| X-03 | 故障机退出、事件重放、版本递增一次、新旧计划保留、真实重算 | 同事件重复请求、两份计划 |
| G4 | DEM/限制区、双跳接入+回传、中继能源/窗口、容量资源、部分保障、Q4 继承 | 独立检查及契约升级 |
| G5 | 同预算稳健/学习消融、场景隔离、防信息泄漏、真实训练日志；ODM/SITL 各自验收 | 原始日志、配置、版本 |
| G6 | 离线安装启动/计算/导出、异常 UI、匿名与来源、正式材料逐项核对 | 重装/断网实测与人工记录 |

总纲 T01–T15 全部保留。原数模最好值仅是历史回归参考，不要求短预算必然重现长搜索最好值，不拿不同模型比较“性能提升”。尚无场景结果时不能记录“零冲突”成功。
