# 演示讲稿与现场流程

先按DEMO_RUNBOOK启动系统。双击demo.cmd可打开15页离线演示稿；建议先讲约4分钟，再做约2分钟软件操作。这里是建议时长，不是已经录制的视频时间。最终文件与验收身份见evidence/demo/manifest.json。

| 页 | 讲述重点 |
|---|---|
| 1 | 援航根据需求、地形和实际机队生成可追溯的运输与通信规划。输出范围是已声明模型内的计划辅助。 |
| 2 | 需求数量与逐箱库存分开，机体与电池逐实体维护。默认5点32箱用于演练，完整原题为15点80箱。 |
| 3 | 算法实际接在后端。点击架次后，地图、箱件和时间轴共同定位；不同策略分别计算，确认前检查模型约束。 |
| 4 | 电池充电结束和机体释放是不同时间。有限准备工位与端口会产生等待，不用画图代替真实排程。 |
| 5 | 退出一个实际使用的电池后，新版本重新安排任务。图中的改派数量来自这次真实运行，旧方案和输入仍可追溯。 |
| 6 | 现场新增需求必须同时新增实物库存。32箱变34箱后重新计算全部任务；不可能的硬截止会保留失败诊断，不发布无效方案。 |
| 7 | 额定单点模型可完整枚举整箱模式。20%余量18架次、30%余量20架次；这里忽略实际资源数量和时限，不能与联合调度当同条件比较。 |
| 8 | 地形和限制区参与路径、时间与能耗计算。自定义GeoTIFF可以连同完整资产包交接。 |
| 9 | 联合方案同时安排运输机、中继机及能源组件，按当前无线/地形模型连续复查覆盖，不是现场无线认证。 |
| 10 | 这是一份独立保存的80箱真实运行：23运输、3中继，联合69.4106kWh。历史分组只作候选，所有物理和时刻重新求解。 |
| 11 | 分区继承同一个联合方案的时序和通信关系，计算各组独立资源与共享损失。冻结配置缺口不等于重新调度的最少增配。 |
| 12 | 容量下界给出完成运输至少需要的架次必要条件，忽略时间和能源。不能把它说成最少无人机或电池数量。 |
| 13 | 增配与参数试算保存独立输入并真实计算。三档压力是确定性情景，不把它说成成功概率。 |
| 14 | 展示最近完整检查点与适用范围；计数从当前源码实际完整验收记录读取。 |
| 15 | 转到本机软件，执行下面的真实流程。 |

## 建议现场操作

1. 新建32箱演练，点击“生成真实方案”。求解期间说明输入已冻结，不能通过修改页面中的数值改变正在运行的任务。
2. 点击架次和箱件，切换电池时间轴。打开“检查报告”，确认后导出JSON或任务CSV。
3. 在“事件复盘”选择“运输电池退出”，选择刚才实际使用的电池，记录故障并重规划。观察版本、路线、机体/电池改派箱件和保持架次。
4. 刷新页面，核对父方案对比和事件记录仍在。需要重新开始时新建演练，不删除旧记录。

时间充足时，额外演示“单点运输诊断”的返航余量切换。80箱通信与分区需要较长真实求解，可提前计算并明确说是已保存方案，不能把历史画面冒充现场新计算。

## 需要如实回答的问题

- “是否全局最优”：一般运输/联合结果为模型内可行的有限搜索；额定单点计数DP和冻结分区只在各自声明的有限模型内完整求解。
- “是否能直接实飞”：当前软件不下发飞控、不接遥测，没有风雨、多机避碰或实地无线认证。
- “修改输入后会怎样”：形成新版本，原方案保持历史来源；当前版本须重新计算和检查后才能确认。
- “是否已经完成全部研究扩展”：没有。AI学习搜索、自动建图与真机仿真需要外部数据/环境，任务板保留这些范围。
- “为什么不是PPTX”：本次环境缺少指定演示工具运行时，已提供可离线放映的HTML和PDF；后续可按赛事官方模板继续整理。
