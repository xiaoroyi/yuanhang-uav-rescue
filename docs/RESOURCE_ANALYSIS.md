# 资源分析与情景试算

入口为事件复盘页的“资源分析与试算”。分析始终读取Plan绑定的不可变Snapshot，不用当前已编辑场景替换历史物理输入。

## 实际计算

GET /api/v1/plans/{plan_id}/analysis返回需求交付、期望延期、硬截止余量、逐机体/电池占用和补能区间。资源占用率分母为该类资源从零点到最后释放；电池包括方案中实际发生的初始补能和返航后补能。并发峰值用左闭右开区间扫描，相同秒先释放后占用。

缺省无限端口时，充电峰值表示模型并发需求；配置resource_limits后，它是有限端口与准备工位约束下的实际计划峰值，等待与初始补能另记。两者都不是最少购买数量证明。硬截止和期望截止分开：期望可以延期；Plan仍必须通过所有要求执行的硬检查。字段和口径见GROUND_RESOURCES.md。

## 独立情景

POST /api/v1/scenarios/{scenario_id}/what-if校验源版本，可绑定同版本source_plan_id。参数支持按机型增机/增电池、能耗/飞行时间倍率、SOH倍率、返航SOC下限，以及仅对无硬截止需求放宽期望时限。所有必须保障需求和硬截止原值保留。

返回独立Scenario和origin；后者与场景版本在同一事务保存到scenario_forks新表，不改写旧数据库表或重置数据。GET /scenarios/{scenario_id}/origin可恢复来源版本、原内容hash、源Plan、变换版本、参数与变更说明。新增实体具有新ID；容量缺省取同型首个已有电池的标称容量，SOC按满电假设，所有电池再统一施加SOH倍率。它是明确的配置情景，不能冒充实测设备。

前端在新Scenario创建Snapshot和真实SolveJob，独立轮询、取消和读取Plan；原场景与原方案保留。结果标明不同输入，不能与同快照策略对比混用；没有把“可行一次”解释为“最少增配”。当前可导出完整分析JSON。

情景历史由GET /scenarios/{scenario_id}/what-if恢复，每条记录保留来源与该情景原始v1对应的Job/Plan。场景后来编辑成v2时仍明确标为“统计原始v1”，不把旧结果配到新参数上。比较面板读取origin绑定的源Plan，切换当前方案不会改变已完成试算的基线。

三档压力检查分别在原输入基础上施加倍率：原值；能耗×1.1/飞行时长×1.05/SOH×0.95；能耗×1.2/时长×1.1/SOH×0.9。每档都是独立场景、快照和真实任务；刷新后记录保留。启发式可能选择不同分批，指标可能非单调，应结合更多搜索复核，不能解释为压力提高有利或真实概率变化。

## 动态稳定性

重规划先建立机体和电池前序依赖图，尝试保留未受影响架次的时间与资源区间；失败则扩大到依赖后继，再在剩余预算全量回退。为准确保留电池SOC，局部模式限初始满电、非充电状态；其他状态使用独立核验的全量法。当前只支持未执行场景的零时刻机体退出。

evidence/solver/replan-comparison.json记录15秒同预算的6组对照：原始截止三种机体故障、移除截止以检验稳定性的三种故障。原截止场景触发全量回退；宽松场景局部保留6个原架次。两者均逐项验证，未声称所有故障都更快、改动最少或全局最优。
