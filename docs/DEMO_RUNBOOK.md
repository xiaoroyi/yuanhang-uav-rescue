# 本机演示与操作手册

本系统用于未执行场景的运输与通信规划。默认真实数据为原题5个较近站点的32箱子集；“更多场景操作”保留完整15点80箱。界面没有登录步骤，日常运行不依赖外部地图服务。

## 启动与数据

在已经配置好的这台电脑双击仓库根目录start.cmd，访问http://127.0.0.1:8000/。服务窗口保持打开，关闭窗口或Ctrl+C停止。场景、版本、任务、方案、事件和确认记录保存在runtime/；不要把该目录当成可随意清理的缓存。测试使用.local/e2e-runtime/，与演示数据分开。

新电脑需要先按README安装项目依赖并构建前端，不能把“本机已准备后的离线运行”理解为任意新电脑无需安装即可运行。GeoTIFF自定义地形移交时，同时导出完整DEM资产包；仅导出场景JSON不包含地形二进制。

## 默认演示：真实计算与动态变化

1. 点击“新建演练”，得到独立32箱场景，不覆盖旧数据。在“调度工作台”点击“生成真实方案”，观察真实阶段和耗时。
2. 完成后点击左侧架次，核对地图高亮、右侧机体/电池/箱件与底部甘特。切换电池时间轴，悬停查看补能与释放；可展开时间轴。
3. 在策略卡“真实计算此策略”计算能耗优先，两次求解使用同一快照。先比较期望延期，再看时间与能耗；不能假定每次搜索都会产生不同方案或所有指标同时改善。
4. 打开“检查报告”，查看硬约束与模型范围，再“确认方案”。确认只预约规划资源，不产生实际飞行或交付事实。下载任务CSV、计划JSON、路线GeoJSON，或打开打印报告另存PDF。
5. 打开“事件复盘 → 动态事件”，选择U01，记录故障并重规划。事件使场景版本增加，新方案绑定新快照；原方案保留。地图旧运输路线为虚线，新路线为实线；下方显示改派箱件和保持架次。
6. 刷新页面，检查场景、最新方案、事件和父方案对比仍可恢复。方案原始快照加载期间不显示混合版本结果；失败时可重试。

还可把事件类型切成“运输电池退出”，选择当前使用的运输电池，观察电池改派箱件和真实新方案。仅改变指定电池可用性，SOC/SOH和位置保留；普通运输和连续通信均有退出后重算证据。相同演练需要多个独立对照时先“新建演练”，不把旧场景强行恢复到初始资源。详见EVENTS。

## 输入变化与资源情景

在“场景与资源”编辑箱件质量/体积、需求时限、机型、机体或电池，保存形成新版本。旧计划仍可查看，但不能作为当前版本确认；回工作台重新计算。需求数量与库存箱件分别维护，删除有关联的数据会得到引用错误，不能静默丢掉需求。

JSON/CSV/XLSX可先预览再导入；Excel与CSV模板包含单位和当前结构。输入中的kg、L、kWh、秒、SOC/SOH必须按字段单位填写。WGS84坐标顺序为经度、纬度。

在“事件复盘 → 资源分析与试算”查看真实占用、充电峰值、期望延期和硬截止余量。增机、增电池或压力参数会创建独立情景和真实任务，原输入保留。三档压力是确定性情景比较，不能当作真实成功概率或稳健最优证明。历史情景标明所统计的原始版本。

## 地形、限制区和地面容量

需要解释机型能力时，在“场景与资源 → 单点运输诊断”查看安全载重与整箱组合。完整原题默认20%返航余量得到18批；切换诊断余量30%得到20批。此切换只改变诊断参数，不修改场景策略。可查看基线、敏感性与独立核查，并导出JSON。它忽略实体数量、充电、时限与通信，不能直接确认执行；正式调度方案仍由工作台生成。详见NOMINAL_ANALYSIS。

- “管理限制区”：创建矩形或导入GeoJSON/JSON并保存。新版本求解会真实绕行，距离、净空、航时与能耗一起更新；地图画出的边界与计算额外缓冲不同，详见SPATIAL_ROUTING。
- “管理DEM资产”：上传单波段米制GeoTIFF，声明高程基准，核对资产后绑定；需要时提取点位高程。覆盖外或NoData不能假装已知安全地形。完整资产包支持跨机导入且保留hash。
- “场景设置”：启用有限准备工位和充电端口，观察真实排队。黄色等待与绿色充电分开；电池排队期间仍被占用。原题未设置容量时保持无限端口模型。

## 通信协同与中继故障

在场景页打开“配置通信资源”，检查原题链路与中继参数，开启“要求全程连续通信”并保存，然后重新生成真实方案。该流程使用60秒搜索预算；可取消或刷新恢复。完成后查看紫色驻点/航线、联合能耗、中继机与能源组件时间轴和实际服务窗口。

运输能耗与联合能耗分开显示；中继累计保障时长按各运输任务相加，可能大于墙钟完成时间。报告中的模型内无缺口不代表现场无线电认证，参数和有限几何范围见COMMUNICATION。

在未执行场景中可选择R01模拟中继机退出。新方案重新安排运输与中继，不能继续引用退出的机体；事件前后比较显示中继架次数和联合指标变化。若当前预算内无法找到方案，旧方案作为历史保留，不能把旧方案当作新状态可执行方案。

## 原题80箱与冻结分区

打开“更多场景操作 → 加载原题80箱场景”，开启通信并重新计算。原题模板会把历史分组与驻点作为候选，仍按当前输入重建全部物理和排程。它不是固定论文回放；更改箱件或资源后必须重新验算。

计算成功后进入“事件复盘 → 冻结任务分区”。切换2/3组及资源/均衡偏好，观察不可拆分单元、工作量、资源峰值、共享损失和库存缺口。展开“峰值见证与实体分配”可逐任务检查。导出JSON保留来源hash、完整分配和精确排序分数。

分区保持原时序与实际通信关系，各组资源独占。同质满SOC/零时刻条件不满足时明确显示限制；库存缺口表示当前冻结任务需要补充资源，不能称原问题无解。详见FROZEN_PARTITION。

## 状态含义

| 状态/提示 | 操作含义 |
|---|---|
| 已验证/FEASIBLE | 当前快照在已声明模型范围内通过独立检查；未证明全局最优 |
| UNKNOWN | 当前输入、候选或预算未得到可发布方案；不是严格无解 |
| INFEASIBLE | 只有模型内已确认的简单必要条件矛盾才报告，例如基地不可用或没有可用运输机 |
| failed / ERROR | 进程或独立检查失败，未发布候选；查看诊断，不反复点击重复提交 |
| 旧版本方案 | 使用其原始快照展示；编辑当前场景不会改变历史输入，重新求解后才能确认新状态 |
| limited分区 | 不满足当前冻结分区模型或规模边界；原联合方案仍保留 |

当前不支持执行中重规划、遥测回写、实际飞控、付费费用模型、训练后的AI搜索、自动摄影测量或真机仿真；这些任务保留在任务板，不以界面占位宣称完成。

在“事件复盘 → 动态事件”选择“紧急需求插入”，填写已有点位、箱数、kg/L、优先级与相对场景零点的截止分钟。系统同步新增等量基地库存并全量重算，旧记录保留。可先增加2箱，再检查34箱完整服务和新增安排统计；若设不可能硬截止，仅保留旧版历史，确认禁用。见EVENTS。
